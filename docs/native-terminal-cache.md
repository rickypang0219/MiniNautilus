# Native terminal-fact cache and rotated-root qualification

Created UTC: 2026-10-18T07:15:00Z.

The next qualification is frozen in `comparisons/native-readiness/rotated-takeover-v1.json`. It adds the combined case missing from the earlier simple-session host tests; it does not replace their results or turn the earlier 45% fill-model error into a pass.

The venue contract already assumes immutable terminal orders and complete, stable execution history on an exclusive Testnet account. The new **volatile, session-local** cache records the original intent/terminal result, complete REST order identity, and SHA256 of those facts plus every raw execution (including fee fields). Only a terminal state already matching the Core, or a complete reconciliation, populates it. A regular poll rechecks the proof against freshly fetched complete execution history and current Core state before reusing status. Missing/changed executions, changed Core terms or uncertainty, damaged proof, and unowned executions stop admission. An active or unverified terminal order still requires REST. The cache makes no new assumption about atomic REST snapshots or trade corrections; those remain unsupported and fail closed when detected.

Full reconciliation clears the cache and runs the original cancel/terminal lookup, complete fills, independent position/cash/funding and foreign-order protocol. Restart starts with an empty cache. A cache does not clear an integrity stop, replace a journal, extend private freshness or justify historical data deletion. It is bounded by the existing 1,000-order segment cap. Polling history/ledger CPU and full reconciliation remain proportional to current-segment history; this change claims only the explicitly tested RPC-count property, not bounded lifetime cost or a measured latency improvement.

Tests cover the original repeated terminal RPC defect, 800 verified terminal plus four active orders, changed fees, missing/foreign fills, corrupt proof and uncertainty. The EC2 release libtest fixture uses the same venue cache and HTTP poll code with a loopback exchange; it is a history-scale correctness fixture, not 804 live orders.

The takeover worker waits for a real completed rotation and an exposed active successor, kills the native/strategy process group, then inventories durable files. The controller confirms EC2 termination before starting a replacement and attaching the same retained encrypted EBS at its original path. It verifies exact pre-recovery bytes and post-recovery append-only prefixes, independently joins all unique venue executions to Core fills, validates the rational ledger and verifies actual flat/no-open-order state. Older sealed journals and cold evidence remain unchanged. This covers process/host replacement with surviving EBS; it does not cover lost EBS/AZ, arbitrary power durability or a second external signer.

Temporary diagnostic long/short exposure is expected. Cleanup must recover the original root, never start a replacement session to hide unresolved actions. State is retained if fresh cleanup cannot be proved. The user's existing host is untouched. The three short drills have a combined USD1 budget; current Tokyo c7i.large compute was queried at USD0.11235/hour, with IPv4 and prorated encrypted gp3 additional. No NAT, ALB or paid endpoint is created. The separate 24-hour qualification remains conditional on the missing correspondence and operations gates; physical elapsed time cannot be replaced by a short run.
